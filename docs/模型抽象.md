# 模型抽象：多提供商支持

> 参考 Suna 的 `internal/model`（adapter.go + router.go + adapter_factory.go），
> 为 agent 加上 Provider 抽象和模型注册表，支持多提供商切换。

---

## 一、为什么需要模型抽象

升级前，agent 只支持一个模型，直接调 OpenAI SDK。问题：

1. **耦合**：runner 直接依赖 OpenAI SDK，换提供商要改代码。
2. **单一**：只能用一个模型，不能"便宜的做日常、强大的做复杂任务"。

升级后：
- **Provider 抽象**：统一接口，换提供商不改上层代码。
- **模型注册表**：配置多个模型，按 ref 切换。

---

## 二、参考 Suna 的架构

| Suna 模块 | 职责 | 我们的实现 |
|-----------|------|-----------|
| `adapter.go` | Provider 抽象接口 | `myagent/providers.py` |
| `adapter_factory.go` | 按协议创建 Provider | `ModelRegistry._create_provider` |
| `router.go` | 模型注册表，按 ref 路由 | `myagent/model_registry.py` |

---

## 三、Provider 抽象（providers.py）

对应 Suna 的 Adapter。所有提供商实现统一接口 `complete()`：

```python
class BaseProvider:
    def complete(self, messages, tools, temperature, max_tokens, stream, on_delta):
        """统一接口：返回 {"content": str, "tool_calls": [..]}"""
        raise NotImplementedError

class OpenAICompatibleProvider(BaseProvider):
    """OpenAI 兼容端点（OpenAI/DeepSeek/Ollama 等）。"""
    ...
```

**价值**：以后接 Anthropic 等不兼容提供商，只需新增一个 Provider 类，上层代码不用改。

---

## 四、模型注册表（model_registry.py）

对应 Suna 的 Router。持有多个模型配置，按 ref 路由：

```python
@dataclass
class ModelConfig:
    ref: str        # 唯一标识，如 "deepseek" / "gpt4o"
    model: str      # 模型名
    base_url: str
    api_key: str
    provider: str = "openai"

class ModelRegistry:
    def get_provider(self, ref): ...   # 按 ref 获取 Provider
    def list_models(self): ...          # 列出所有模型
```

---

## 五、配置多模型

主模型用 `MY_AGENT_MODEL/BASE_URL/API_KEY`，额外模型用 JSON：

```bash
MY_AGENT_MODELS=[{"ref":"gpt4o","model":"gpt-4o","base_url":"https://api.openai.com/v1","api_key":"sk-xxx"}]
```

## 六、代码结构

```
myagent/
├── providers.py        # Provider 抽象（BaseProvider + OpenAICompatibleProvider）
├── model_registry.py   # 模型注册表（ModelConfig + ModelRegistry）
├── runner.py           # 用 Provider 代替直接调 OpenAI SDK
├── agent.py            # 建注册表，按 ref 取 Provider
└── config.py           # 支持多模型配置
```
