# 记忆升级：持久化 + token 裁剪

> 参考 Suna 的 `internal/memory`（store.go + compress.go），
> 为 agent 加上会话持久化和 token 级上下文裁剪。

---

## 一、为什么升级

升级前有两个明显短板：

1. **重启就丢**：会话历史只存在内存里，关掉程序就没了。
2. **无脑重发**：每次对话把全部历史重发给模型，浪费 token，还可能撑爆上下文。

升级后：
- **持久化**：用 SQLite 保存会话和消息，重启能接着聊。
- **token 裁剪**：按 token 预算裁剪旧消息，省 token 更稳。

## 三、持久化（store.py）

用 Python 标准库 `sqlite3`，不引入新依赖。

### 表结构
```sql
sessions (id, title, created_at, updated_at)
messages (id, session_id, role, content, tool_call_id, created_at)
```

### 关键设计
- **系统提示词不持久化**：它由 Agent 每次启动重新注入，存了会重复。
- **消息带 tool_call_id**：工具结果能正确回填。

### 使用
```bash
# .env 里配置 DB 路径
MY_AGENT_DB_PATH=myagent.db
```

启动时选择会话：
```
=== 已有会话 ===
  1. 测试会话  (3 条消息)
  2. 新建会话
选择会话编号: 1
```

## 四、token 裁剪（memory.py）

### token 估算
不引入 tiktoken，用启发式：`tokens ≈ len(text) // 2`（中英文混合约 1 token ≈ 2 字符）。

### 裁剪策略（参考 Suna compress.go）
- 系统提示词永远保留在最前面。
- 超过 token 预算时，**保留最近消息直到接近预算，丢弃最旧的**。
- 兜底：再按条数裁剪（`max_history`）。

```python
def _trim_by_tokens(self, messages):
    if self._estimate_tokens(messages) <= self.max_tokens:
        return messages
    kept = []
    total = 0
    for m in reversed(messages):
        t = estimate_tokens(m.get("content", ""))
        if kept and total + t > self.max_tokens:
            break
        kept.append(m)
        total += t
    kept.reverse()
    return kept
```

### 配置
```bash
MY_AGENT_MAX_TOKENS=8000   # 上下文 token 预算
```
